# 移动端适配说明（2026-11-05）

起因：有人反馈手机打开页面「不兼容」。实测确认问题存在，本次按真机尺寸做了适配。

## 一、改前是什么样

用 390×844（iPhone 12/13/14 逻辑尺寸）实测，问题集中在快讯流：

| 现象 | 原因 |
| --- | --- |
| 日历和人气榜被挤成左右两栏，证券名、更新时间全被截断 | `≤1240px` 断点把右栏 `order:-1` 并排两列，那是给平板和窄桌面用的，手机上仍然生效 |
| 首屏全是日历和人气榜，新闻被挤到第二屏 | 同上，右栏置顶 |
| 顶部五个导航标签只露出三个，「开市日历」「接口设置」要横滑才找得到 | 标签条没去掉图标，390px 放不下 |
| 筛选区占四行，把内容推到很下面 | 每个控件的内边距按桌面尺寸给 |
| 导入记录表格七列被压成一条条竖缝，表头读不出来 | `table-layout:fixed` + 百分比列宽，在 390px 下每列只剩三四十 px |

改前截图见 `docs/ui-preview/03-mobile-390.png`。

## 二、改了什么

全部是 CSS，没有动结构和 JS，桌面端不受影响（规则都在 `max-width:820px` 及更小的媒体查询里）。

| # | 改动 | 位置 |
| --- | --- | --- |
| 1 | 右栏退回单列，取消 `order:-1`，放到新闻流之后；两张卡强制等宽 | `index.html` / `index-core.html` 第 24 节 |
| 2 | 筛选区隐藏「日期」「信息重要度」两个说明文字，控件高度统一到 34px，统计单独占一行 | 同上 |
| 3 | 导航标签去掉图标、收紧内边距，390px 一屏放完；360px 再收一档 | 同上 |
| 4 | 表格改 `table-layout:auto` + `min-width:620px`，在 `.tblwrap` 里横滑；空表时收起表头，避免居中文字被裁 | 同上 |
| 5 | 新闻卡片时间列 58px → 46px，把宽度让给正文 | 同上 |

顺带把月切换按钮从 26×26 放大到 34×34，手指能按准。

## 三、验证方式

新增 `tools/ui-mobile.cjs`，用 CDP 精确设置视口（Edge 无头默认会把视口钳到 508px，必须用 `Emulation.setDeviceMetricsOverride` 才能拿到真实宽度）。

```powershell
PORT=8799 python -B deploy/show-v2/app.py
node tools/ui-mobile.cjs http://127.0.0.1:8799 9330 390
node tools/ui-mobile.cjs http://127.0.0.1:8799 9330 360
```

每次运行会逐个屏检查并输出：

- 文档是否横向溢出（`scrollWidth > clientWidth`）
- 哪些元素超出视口右边界，附选择器与超出量
- 点击目标小于 32×32 的数量

实测结果：

| 宽度 | 横向溢出 | 过小点击目标 | 结论 |
| --- | --- | --- | --- |
| 390 | 无 | 16（改前 46） | 通过 |
| 360 | 无 | 16 | 通过 |
| 1280（回归） | 无 | — | 桌面布局未受影响 |

截图在 `docs/ui-preview/mobile/`，390 的五屏各一张加两张滚动截图，360 保留快讯流一张作小屏佐证。

## 四、没做的

| 项 | 原因 |
| --- | --- |
| 360px 下搜索框只剩约 60px，placeholder 显示不全 | 品牌名和「示例数据」标识都要保留，再挤就会牺牲状态提示；能点能输，暂不处理 |
| K 线抽屉、深度分析里的图表 | 抽屉默认收起，展开后是横滑容器，本轮未逐项实测 |
| 横屏（844×390） | 未单独适配，横向空间等同 844px 平板，走的是 `≤1240` 那套规则 |
| 抽公共样式表 | 两份 HTML 各有一份相同 CSS，本次按既有做法两处同步 |

## 五、后续如果要继续改

1. 真机上发现问题，先用 `ui-mobile.cjs` 跑一次，看输出的溢出元素选择器，比肉眼找快
2. 改完在 390 和 360 各跑一次，确认「无横向溢出」且过小点击目标没有回升
3. 改 `index.html` 时记得同步 `index-core.html` 的同名样式块
