## 2. A 册 · 前端 UI / 交互逻辑 Bug（建议按此顺序修）

### A1 · P0 · 右栏脚注输出 `undefined（周undefined）`

- **现象**：快讯流右栏「开市日历 · 本周」下方恒定显示 `下一次调休上班：undefined（周undefined）—— 上班但不交易。`，浅色/深色、桌面/移动端、四个屏均可见，是对外展示站最刺眼的缺陷。
- **复现**：任意屏加载后读 `#weekNote.textContent`。
- **定位**：`deploy/show-v2/index.html:2001–2004`
  ```js
  const nx = MAKEUP_DAYS.filter(d=>d>TODAY).sort()[0];
  ... : `下一次调休上班：<b>${nx}</b>（周${WD[parseD(nx).getDay()]}）—— ...`;
  ```
- **根因（前端边界条件）**：`MAKEUP_DAYS`（`:1228`）硬编码了 2026 年 6 个调休上班日，最后一个是 `2026-10-10`。当前日期 2026-11-04 之后无剩余项，`filter()[0]` 返回 `undefined`，模板字符串直接插值；`parseD(undefined)` 又让星期取值变成 `undefined`。**且该表只含 2026 年，跨年后会整体失效。**
- **建议修法**：加空值分支，例如 `nx ? 原文案 : '本年度已无剩余调休上班日。'`；并把 `MAKEUP_DAYS` / `HOLIDAY_TABLE` 标为年度数据，提醒每年更新（或在 `docs/` 记一条年度维护项）。
- **影响范围**：`MAKEUP_DAYS.filter` 在 **全部 5 个前端页面**都存在（含 V1）。V1 受哈希保护，是否同步需小组决定（见 B 册末尾）。

### A2 · P0 · 「开始 AI 分析」在示例数据态静默无反馈 + 提示写死旧端口

- **现象**：点击 `#anaRun` 或 `#aiRunInline`，`aiStatus` 完全不变（前后都是 `当前是示例数据，请先通过 http://127.0.0.1:3000 打开网站。`），没有 loading、没有禁用、没有提示，用户无法判断按钮是否生效。且 `3000` 是**旧版 Node 的默认端口**，与当前 Python 展示站（本地 8765 / 线上 `mf12.show.lingnan.top`）不符。
- **复现**：进入智能分析 → 点「开始 AI 分析」→ 读 `#aiStatus`。
- **定位**：`:2363` `if(!n || dataMode!=='live') return;`（静默返回）；`:2359` 硬编码地址。
- **归属判断**：**是否启用真实分析由后端同学决定，但按钮在不可用态下的禁用/提示属于前端设计逻辑，归你负责。**
- **建议修法**：① 去掉写死的端口，改为「当前为示例数据模式，接入数据服务后可发起 AI 分析」之类的相对表述；② `dataMode!=='live'` 时把两个分析按钮设为 `disabled` 并给出 `title`，或在点击时更新 `aiStatus` 明确说明原因，避免「点了没反应」。

### A3 · P0 · 手动刷新后筛选状态被「部分重置」

- **现象**：依次设置 `标签=宏观级 → 仅看收藏=开 → 排序=按重要度`，列表为 1 条；点击「手动刷新」后变成 **4 条**（标签筛选仍在，收藏/排序/星级/日期被清空），但界面上「仅看收藏」「按时间倒序」等控件的可见状态与实际过滤条件不一致。
- **复现**：按上述顺序操作，对比步骤 `09-fav-only` / `10-sort-stars` / `12-manual-refresh` 的 `feed` 计数（1 → 1 → 4）。
- **定位**：`:1681–1689 resetLiveFeedFilters()`
  ```js
  state.filters={date:null,stars:0,tag:'all',sort:'time',favOnly:false}; // 全部重置
  ...
  syncTagOptions();  // :1679 又用当前 select 值把 state.filters.tag 改回「宏观级」
  ```
- **根因（前端状态管理）**：`syncTagOptions()` 的「保留用户选择」语义与 `resetLiveFeedFilters()` 的「全部重置」语义冲突，导致混合态；且刷新前没有任何提示。
- **建议修法**：明确一种策略并贯彻——**要么**刷新时全部重置，并同步把标签 `select` 也置回 `all`（在 `syncTagOptions` 里加「重置」参数）；**要么**刷新时完整保留所有筛选。不要两头不靠。若选择重置，建议在刷新完成时给一句轻提示「已更新新闻并重置筛选」。
- **影响范围**：deploy 展示站、`versions/feedback` 两个页面、`modules/news/prototype/index-core.html`（V1）。`frontend/index.html` 无此函数。

### A4 · P1 · 主题切换不持久化

- **现象**：切到深色后 `localStorage` 完全为空（`lsKeys: []`），刷新页面即回到浅色。
- **复现**：步骤 `42-theme-persist`。
- **定位**：`:1857–1859`，只改 `document.documentElement.dataset.theme`，未读写存储。
- **建议修法**：切换时写入 `localStorage`，初始化时（尽早，避免闪白）读取并应用；同时尊重 `prefers-color-scheme` 作为首次默认值。
- **影响范围**：全部 5 个页面都有 `themeBtn`。

### A5 · P1 · 「开始打标」按钮可用性状态缺失

- **现象**：导入记录表有 1 行，但无 `pending` 项时点击「开始打标」只把 `#importStatus` 改成「当前没有待打标新闻。」，弹层未打开；按钮仍是**主按钮高亮**，视觉上完全可点。
- **定位**：`:2298–2302`。
- **建议修法**：渲染导入记录后同步更新按钮状态——无 pending 时 `disabled` + 置灰 + 文案改为「暂无待打标新闻」；有 pending 时恢复可点。

### A6 · P1 · favicon 404

- **现象**：每次加载 `/favicon.ico` 返回 404，console 出现 2 条错误（是本轮 4 条事件里唯一的「非预期」项）。
- **建议修法**：在 `<head>` 加一行 `<link rel="icon" href="data:,">`，或放入一个品牌图标文件。前端一行即可解决，不必麻烦后端。
- **影响范围**：全部 5 个页面都没有 favicon 声明。

### A7 · P2 · 筛选空状态缺少「一键清除」

- **现象**：搜索/筛选无结果时只有一句「当前筛选条件下没有快讯」，用户必须自己逐个控件恢复（搜索框、星级、标签、收藏、排序、日期共 6 处）。
- **定位**：`:2076–2077` 的空状态卡片。
- **建议修法**：在空状态卡片加「清除全部筛选」按钮，复用 `resetLiveFeedFilters()`（正好与 A3 的修复一起做）。

### A8 · P2 · 相关公司计数与占位行口径

- **现象**：筛选「事件直接相关」后计数为「显示 0 / 7 只」，但 `#tblBody` 有 1 行（那行是「当前筛选条件下没有可展示标的」提示）。DOM 计数与视觉容易误读。
- **定位**：`:2721–2728`。这属于**展示口径**而非计算错误。
- **建议修法**：空状态行加 `aria-label` / `role="status"`，或把计数文案改为「0 只（共 7 只）」。优先级低。

| 现象 | 实测值 | 说明 |

## 4. C 册 · UI 美化清单（Bug 修完后再做）

按「收益 / 改动量」排序，均为纯前端视觉与体验层：

6. **抽公共样式表**：3 个页面的 `<style>` 块原本完全一致，长期各自维护必然分叉；建议单独一个 PR 处理。

## 5. 复现与验收

```bash
# 1) 启动服务（保持数据目录在系统临时目录，避免污染仓库）
cd AI智能体设计/FinSight/deploy/show-v2
PORT=8765 DATA_DIR="$TEMP/finsight-runtime-data" python -B app.py

# 2) 另开一个终端跑检查（Windows 需 Edge；可用 EDGE_PATH 覆盖路径）
cd AI智能体设计/FinSight
node tools/ui-smoke.cjs http://127.0.0.1:8765 9224
```

脚本会输出每一步的 DOM 状态，并生成 `docs/ui-preview/smoke/report.json` 与截图。**修完 A 册后重跑，验收标准**：

- `report.json` 中任一步 `state.bad` 不再出现 `undefined`（A1）；
- 步骤 `12-manual-refresh` 的 `feed` 计数与刷新前筛选条件一致，或控件状态已同步（A3）；
- 步骤 `33-ai-run-feedback` 的 `aiStatus` 相对点击前**有变化**，且不再含 `127.0.0.1:3000`（A2）；
- 步骤 `42-theme-persist` 的 `savedTheme` 不再是 `null`（A4）；
- `errors` 中不再出现 `favicon.ico` 404（A6）；
- 步骤 `29-mobile-390` 仍保持 `vw === sw === 390`（不因修复引入横向溢出）。

> 脚本只做只读界面操作，不向外部服务写数据；提交内网地址那一步是故意触发 SSRF 防护以验证前端错误提示。
